# 밤사이 — PRD (제출용 요약)

> 국내 시장이 닫힌 밤과 주말에도 24시간 운영되는 해외 선물 탈중앙 거래소 **하이퍼리퀴드**에서 한국 주식이 거래됨.
> 이 가격을 원화로 바꿔 **① 밤사이 해외 가격과, 과거에 국내 시장이 그 방향대로 열린 비율**, **② 지금 두 시장 사이 시세차익 기회가 있는지** 알려줌.
> 웹앱 **https://bamsai.kr** · GitHub https://github.com/eddyParkGG/bamsaikr · API·MCP [bamsai.kr/developers](https://bamsai.kr/developers) · 자세한 내용 [README](../README.md)

## 1. 문제와 고객

| | 내용 |
|---|---|
| **문제** | 국내 시장(정규장 + 넥스트레이드, 08:00–20:00)은 주 168시간 중 35%만 열림. 나머지 65% 동안 생긴 일이 다음 날 장 시작 가격에 어떻게 반영될지 개인은 알 방법이 없음 |
| **답이 있는 곳** | 하이퍼리퀴드 한국 주식 perp는 24시간 거래 (SK하이닉스 24시간 거래대금 약 5.4억 달러). 단, 달러(USDC) 표시라 원화 환산·수수료 계산이 필요 |
| **핵심 고객** | 삼성전자·SK하이닉스를 보유한 30~40대 직장인. 아침 8시 국내 시장이 열리기 전에 매일 판단할 일이 있음 |
| **확장 고객** | 주식·코인 겸업 트레이더(시세차익), AI 툴로 자기만의 투자 도구를 만드는 고객(API·MCP로 같은 숫자를 에이전트에서 바로 씀) |

## 2. 가설과 검증

| # | 가설 | 상태 |
|---|---|---|
| **H1 신호** | 국내 시장이 모두 닫힌 20:00~08:00에 하이퍼리퀴드에서 충분히(100만 달러 이상) 거래됐다면, 그 방향대로 다음 날 08:00 국내 시장이 시작한다 (80% 이상) | **삼성전자 88.2%·SK하이닉스 85.4% 통과(11/5 기준), 현대차 판단 보류** (거래 충분한 밤 7번뿐) |
| H2 가치 | 밤사이 해외 가격과 '그 방향대로 열린 비율'을 보여주면 장 시작 전에 다시 온다 | 커뮤니티 4일 실험 예정 (개장 전 재방문 ≥ 15%) |
| H3 신뢰 | 지난 개장 기록을 같이 보여줘야 믿고 행동한다 | 근거 열람률 ≥ 10% |
| H4 전환 | 비용 뺀 시세차익 기회를 보여주면 주문 버튼 클릭으로 이어진다 | 클릭 ≥ 5%, 출시 알림 신청 ≥ 20% |
| H5 에이전트 | API·MCP를 열면 화면 밖 호출이 생긴다 | 주 1,000회 |

**H1 채점 기준**: 전날 20:00 국내 마지막 가격 대비, 08:00 하이퍼리퀴드 가격(원화)과 08:00~08:10 국내 평균 가격이 같은 방향인지.
기간 2026-04-13 ~ 11-05, 종목별 139번 (±0.05% 안쪽은 제외). 정규장만 보던 이전 기준(15:30 → 09:00)은 넥스트레이드에서 이미 보이는 움직임까지 예측으로 쳐서 91%대로 부풀려졌기에 바꿈.
거래대금 조건: 백테스트에서 거래대금별 적중률을 비교해 100만 달러로 정함(미만 67.3% vs 이상 86.3%, 세 종목 합산). 같은 데이터로 고른 기준이라 0~500만 달러로 바꿔 다시 확인했고 85~89%로 거의 같았음. 기준 미만인 밤에는 '거래 적어 덜 정확' 표시.

**언제 본 가격이냐**: 밤사이 하이퍼리퀴드는 미국장 동안 가장 크게 움직임. 같은 방식으로 시각별로 채점하면(평일 밤 108번) 21시 가격은 49%, 미국장이 닫힌 06시 가격은 86~87%만 방향이 맞음. 그래서 화면은 지금 시간대에 맞는 과거 적중률을 같이 보여줌.

## 3. 예측 계산법

1. 밤사이 차이 `g` = 지금 하이퍼리퀴드 가격(원화) ÷ 어제 20:00 국내 가격 − 1
2. 예상 움직임 `μ` = α + β·g (과거 개장에서 국내가 하이퍼리퀴드를 따라간 정도. β는 1 쪽으로 당겨 안정화)
3. 불확실성 `σ` = 과거 빗나간 폭(평일 밤 / 주말 따로) + 장 열리기까지 남은 시간만큼의 하이퍼리퀴드 변동성
4. 보통 시작하는 범위(80% 구간) = μ ± 1.28σ. 그날 이전 데이터로만 계산해 채점 (walk-forward). 오를 확률 Φ(μ/σ)은 API에만 두고 화면에서는 쓰지 않음 (확률이 약속처럼 읽혀서)

**예시 — SK하이닉스 11/4 아침**: 어제 20:00 1,414,000원 → 08:00 하이퍼리퀴드 +3.37% → 범위 약 1,428,000~1,477,200원 → **실제 1,451,776원(+2.67%), 하이퍼리퀴드 방향대로 열렸고 범위 안**

## 4. 해결 방법 (프로토타입)

| 화면 | 답하는 질문 | 핵심 요소 |
|---|---|---|
| 홈 | "밤사이 해외에선 얼마나 움직였어요?" "지금 시세차익 기회 있어요?" | 종목 카드: 장중엔 국내 지금 vs 개장 직전 글로벌 가격, 장 마감 후엔 국내 종가 vs 지금 글로벌 가격 + 과거 이 시간대 '그 방향대로 열린 비율'. 비용 뺀 시세차익 |
| 종목 상세 | 두 시장이 어디서, 얼마나 벌어졌나 | 차트 \| 호가 \| 주문 한 화면, 차트 위에 하이퍼리퀴드 지금 가격·미국장 단계·시세차익 기회, 주문(출시 예정 + 알림 신청), 지난 개장 기록 |
| API · MCP | 에이전트가 같은 정보를 쓰려면? | 조회·주문 미리보기, MCP 도구 |

**시세차익 기회** = |가격 차이 − 평소 차이| − 주식 수수료·세금 − 하이퍼리퀴드 수수료 − 환전 비용 − 펀딩비. 두 시장 차이는 0이 아니라 평소 수준(최근 5거래일 정규장 중간값, 11월 약 +0.5%)으로 돌아가므로, 평소보다 더 벌어진 만큼만 기회로 봄. 공매도가 어려운 개인 기준으로 실행 불가한 방향은 기회로 세지 않음. 호가 중간 가격 기준이라 잔량·슬리피지는 미반영(한계).

## 5. 지표와 결정 규칙

- **North Star**: 미국장이 닫힌 뒤 국내 시장 시작 전(06:00~08:00)에 밤사이 가격을 실제로 본(`prediction_view`, `kst_window=preopen`) 주간 사용자. 단순 방문은 세지 않음. 11/6 GA 맞춤 측정기준 등록 후 값이 쌓이는 것 확인. 첫 개장 전(06~08시) 집계는 11/9(월) 아침부터
- **첫 실험**: 디시 주식 갤러리 4일 게시(네이버 종토방은 홍보 금지로 제외) → 첫 방문자 중 다음 개장 전 재방문 **≥ 15%면 개장 전 알림 개발**, 5~15%면 메시지 바꿔 재실험, 5% 미만이면 습관 가설 기각
- **가드레일**: 하이퍼리퀴드 방향 적중 4주 연속 75% 미만이면 예측 숨김. 레버리지 5배 이상 주문 비중 감시

## 6. 주요 결정

| 결정 | 이유 |
|---|---|
| 시세 호출은 그룹별 대기열 + 공유 캐시 | 토스 API는 그룹별 초당 한도가 있음. 그룹마다 한도 아래로 줄 세우고, 과거 봉은 길게·최신 봉만 자주 받아 접속자가 늘어도 호출 수가 늘지 않게 함 (11/6 한도 초과 1~2초마다 → 분당 0~2회). 자세한 운영 기록은 README '운영하며 고친 것' |
| 국내 시세는 프로토타입용 토스증권 개인 Open API | 카카오페이증권은 오픈 API가 없음. 토스 약관상 시세는 본인 매매 목적만 허용돼 공개 서비스에는 맞지 않음 → 실제 출시는 증권사가 계약한 정식 시세(코스콤 등) 전제. 무료 공공 데이터(KRX·금융위)는 일별이라 넥스트레이드 분봉을 대체 못 함 |
| 국내 시장 = 정규장 + 넥스트레이드 | 개인이 거래할 수 있는 시간 전체. 정말 닫힌 20:00~08:00만 예측 대상 |
| 환율은 업비트 원/USDC | 하이퍼리퀴드는 USDC 정산. 실제 돈이 옮겨가는 경로 |
| 단순 선형 모델 | 종목별 140번 남짓 표본 → 과적합 방지, 초보에게 설명 가능 |
| 주문은 '출시 예정' + 알림 신청 | 실수 주문 0건, 대신 수요(H4) 측정 |
| 해외 perp 거래 권유 안 함 | 국내 투자자 보호 대상이 아님. 조회와 판단까지만 |

## 7. AI 활용과 운영

- **AI는 만드는 도구로만**: Claude Code로 리서치(API 스펙·수수료 구조), 데이터 검증(환산가·통합 시세 차이), walk-forward 백테스트, 구현, 브라우저 QA. 제품 안의 숫자는 LLM이 아니라 통계 계산이 만듦
- **AI 결과를 고친 사례**: 저녁 9시 '내일 +0.3%'가 실제 −11.9%로 빗나감 → 시각별 재채점(21시 49% vs 06시 86~87%) → '오를 확률'을 빼고 '미국장 마감 뒤 가격 + 과거 비율'로 전환. 외부 AI 리뷰는 채택(지표 통일·민감도 표)과 거절(AI 야간 브리핑)을 나눠 결정
- **운영하며 고친 것 (11/6)**: CDN zstd 캐시로 iPhone 로딩 실패 → 서버 gzip / 토스 그룹별 한도 초과 → 그룹별 대기열·증분 캐시(한도 초과 1~2초마다 → 분당 0~2회, 접속자 수와 무관) / 과거 가격 환산을 그 시각 환율로 / 차트 실시간 봉 / API·MCP 사용량을 GA `api_call`로 측정(H5)
