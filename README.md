# 밤사이

국장이 닫힌 밤과 주말에도 거래되는 **하이퍼리퀴드 한국 주식 perp** 가격으로
**① 다음 날 장 시작 가격가 오를지 내릴지**, **② 지금 두 시장 차이로 얼마가 남는지** 알려주는 서비스

- 웹앱: `배포 후 추가`
- API 문서: `/api/openapi.json` · MCP: `/api/mcp` · 화면 안내: `/developers`

| 항목 | 내용 | 자세히 |
|---|---|---|

| **AI 활용** | Claude Code로 리서치·데이터 검증·모델 백테스트·구현·브라우저 QA | [AI 활용 과정](#ai-활용-과정) |

# PRD

## 한 줄 요약

국장이 닫혀 있는 81%의 시간 동안에도 삼성전자·SK하이닉스·현대차 가격은 해외 24시간 시장에서 움직임.
이 가격을 원화로 바꿔 **다음 장 시작 가격의 방향과 범위**를 확률로 보여주고, 장중에는 **비용 뺀 실제 차익**을 계산해 주문까지 연결.

## 1. 해결하려는 문제

| # | 누가 | 문제 | 지금은 어떻게 하나 |
|---|---|---|---|
| P1 | 삼성전자·하이닉스 보유 개인 | **"내일 아침 오를까, 내릴까?"에 답할 근거가 없음.** 미국장 끝난 뒤, 주말·연휴 동안 생긴 뉴스가 다음 날 장 시작 가격에 얼마나 반영될지 모름 | 미국 지수, ADR, 커뮤니티 분위기로 짐작 |
| P2 | 주식·코인 같이 하는 트레이더 | **두 시장 차이를 보려면 창 3개(하이퍼리퀴드, HTS, 업비트 환율)를 띄우고 직접 계산.** 수수료·세금·환전·펀딩비를 빼면 실제로 남는지 알 수 없음 | 엑셀, 감으로 판단 |
| P3 | 자동매매·AI 에이전트 사용자 | 두 시장 시세·괴리·예측을 **한 번에 조회하는 API가 없음** | 거래소별 API 따로 붙여서 직접 구현 |

**문제의 크기 (2026-11-05 직접 조회)**

- 국장 정규장은 주 32.5시간(주 168시간의 19%). 넥스트레이드를 포함해도 60시간(36%)
- 하이퍼리퀴드 `xyz:SKHX`(SK하이닉스) 24시간 거래대금 **약 5.4억 달러**, `xyz:SMSN`(삼성전자) 약 0.9억 달러
- perp 상장(2026-02-20) 이후 국장 개장 139번 중 **32번이 주말·연휴 뒤 개장**

## 2. 타겟 고객

| 구분 | 고객 | 이 고객을 고른 이유 | 모드 |
|---|---|---|---|
| **핵심(Beachhead)** | 삼성전자·SK하이닉스를 **보유한 30~40대 직장인 투자자** | 개인 보유자가 많은 대표 종목이고 perp 거래대금도 가장 큼. 장 시작 전(출근길 08~09시)에 판단할 일이 매일 있음 | 홈 |
| 확장 1 | 업비트·하이퍼리퀴드를 같이 쓰는 **주식·코인 겸업 트레이더** | 이미 perp를 알고 있어서 설명 비용이 낮고, 차익·갭 매매로 주문 전환 가능성이 큼 | 종목 화면 |
| 확장 2 | 에이전트·자동매매를 직접 만드는 **빌더** | 과제 배경과 같은 흐름. API 하나로 쓰는 유입 채널 | API · MCP |

**하지 않는 것**: 해외 perp 거래 권유. 국내 투자자 보호 대상이 아니라서 홈은 '조회와 판단'까지만 제공함 (금융위·금감원 2026-10-16 유의사항 발표)

## 3. 가설

가장 위험한 가정부터 순서대로 검증.

| # | 가설 | 위험도 | 이 가설이 틀리면 |
|---|---|---|---|
| **H1 모델** | 개장 직전 perp 원화 환산가로 **다음 날 장 시작 가격 방향을 80% 이상** 맞힐 수 있다 | 가장 높음 | 서비스 존재 이유가 없음 |
| **H2 가치** | 보유 종목의 "오를 확률"을 보여주면 **장 시작 전에 다시 찾아온다** | 높음 | 신기한 숫자로 끝나고 습관이 안 됨 |
| **H3 신뢰** | 과거 적중 이력을 같이 보여줘야 **확률을 믿고 행동한다** | 중간 | 숫자만 보고 떠나거나, 반대로 맹신 |
| **H4 전환** | 수수료·세금까지 뺀 **순차익**을 보여주면 조회가 **주문 미리보기**로 이어진다 | 중간 | 종목 화면이 구경용에 그침 |
| **H5 에이전트** | 조회 API·MCP를 열면 **화면 밖 호출(에이전트)** 이 생긴다 | 낮음 | 개발자 채널을 접고 앱에 집중 |

**H1은 출시 전 백테스트로 먼저 검증** (그날 이전 데이터로만 학습 → 그날 예측, walk-forward)

| 종목 | 방향 적중 | 80% 구간 실제 포함 | 시작 가격 오차 | 비교: 전일 종가 그대로 |
|---|---|---|---|---|
| 삼성전자 | **89.9%** | 86.6% | 0.89%p | 2.91%p |
| SK하이닉스 | **89.1%** | 81.5% | 0.89%p | 3.35%p |
| 현대차 | **84.0%** | 74.8% | 0.97%p | 1.75%p |

- 기간: 2026-02-20 ~ 2026-11-05, 종목별 개장 119번 검증 (처음 20번은 학습용)
- 기준: KRX 정규장 시작 가격(09:00)·종가(15:30). 토스증권 분봉에서 추출 (일봉은 넥스트레이드 포함 통합 시세라 쓰지 않음)
- 결론: **H1 통과.** 다만 현대차는 80% 구간 포함률이 74.8%라 구간을 조금 좁게 잡고 있음. 출시 후 재보정 대상
- 화면에서도 같은 숫자를 매일 다시 계산해 공개 (H3 검증 장치)

## 4. 검증 지표

**North Star: 개장 전(08:00~09:00) 예측을 확인한 주간 사용자 수**
→ 선정 이유: H2(습관)와 H1(모델 신뢰)이 둘 다 맞아야 오르는 숫자. 단순 방문자 수가 아니라 '장 시작 전 판단'이라는 핵심 행동만 셈

### 첫 실험: 커뮤니티 4일 테스트

| 항목 | 내용 |
|---|---|
| 목적 | H2(개장 전에 다시 오나)를 가장 싸게, 가장 빨리 확인 |
| 채널 | 네이버 종목토론방(삼성전자·SK하이닉스), 디시 주식 갤러리 |
| 시점 | **국장 마감 후(15:30 이후)** 게시. 목·금·일 저녁 3회 → 금·월 개장 전 재방문 측정 (주말 갭 포함) |
| 기간 | 4일 (목 마감 ~ 월 09:00) |
| 메시지 A/B | A 예측형 "내일 장 시작 가격, 오를 확률 56%" / B 사실형 "지금 해외에선 삼성전자 -2.6%" |
| 추적 | 글마다 `utm_source`(naver_jongto, dc_stock) + `utm_content`(종목_요일_A/B). 첫 유입 채널을 사용자 속성으로 저장 |
| 판단 최소 표본 | 방문자 200명. 미만이면 결론 보류, 게시 1회 추가 |

| 단계 | 지표 | 성공 기준 | 근거 | GA4 |
|---|---|---|---|---|
| 유입 | 게시글 조회 대비 방문 | **≥ 3%** | 커뮤니티 링크 클릭률 통상 1~3% 가정. 3%를 넘으면 문제 자체에 관심 있다고 판단 | `session_start` × `first_source` |
| 활성화 | 방문 → 예측 확인 | **≥ 70%** | 첫 화면에 바로 보여서 이보다 낮으면 첫 화면 문제 | `prediction_view` |
| 활성화 | 예측 → 종목 상세 | **≥ 30%** | 숫자 하나 보고 이탈하는지, 근거를 더 보는지 | `prediction_detail_open` |
| **핵심 리텐션** | 첫 방문 다음 개장 전 재방문 | **≥ 15%** | 커뮤니티발 일회성 유입의 D1 재방문은 보통 5~10% 수준으로 가정. 그 두 배면 '습관' 신호 | `page_view` (`kst_window`=preopen) |
| 리텐션 | 4일 중 2일 이상 방문 | **≥ 20%** | 주말 갭이 있는 월요일까지 다시 오는지 | 코호트 탐색 |
| 신뢰 | 근거 펼침 | **≥ 10%** | 확률만 보고 믿는지, 근거를 확인하는지 | `model_explain_open` |

**판단 규칙**

- 개장 전 재방문 **15% 이상** → 개장 전 알림(웹 푸시) 바로 개발. 알림이 리텐션을 더 올릴 여지가 큼
- **5~15%** → 메시지(A/B 중 나은 쪽)와 게시 시각을 바꿔 1회 재실험
- **5% 미만** → '매일 보는 습관' 가설 기각. 주말·연휴 갭 리포트처럼 이벤트성 콘텐츠로 방향 전환
- A/B는 채널 간 차이보다 메시지 차이를 먼저 봄 (채널은 2개뿐이라 비교 의미가 약함)

**주의할 점**

- 커뮤니티 홍보 금지 규정: 정보 공유 형식(주말 갭 수치 + 그래프 캡처)으로 쓰고 링크는 1개만
- 특정 종목 매수·매도 권유 문구 금지 (유사투자자문 오해 방지)

### 출시 후 지표 (실험 통과 시)

| 가설 | 지표 | 목표 (4주) | GA4 이벤트 |
|---|---|---|---|
| H1 | 방향 적중률 / 80% 구간 포함률 | ≥ 80% / 75~85% | 서버 계산, 화면 공개. 4주 연속 75% 미만이면 노출 중단 |
| H3 | 근거 펼친 사람의 재방문율 차이 | +10%p | `model_explain_open` |
| H4 | 차익 조회 → 주문 미리보기 | ≥ 5% | `arb_view` → `order_preview` |
| H4 | 미리보기 → 실제 주문 | ≥ 20% | `order_preview` → `order_submit` |
| H5 | 주간 외부 API 호출 | 주 1,000회 | 서버 로그 `api_call`, `mcp_copy` |

**가드레일 (나빠지면 바로 멈춤)**

- 예측 오차 3%p 이상인 날의 비율 (오라클 이상, 상한가·하한가 날 포함)
- 종목 화면 주문 중 메인넷 비중, 레버리지 5배 이상 비중
- 홈에서 들어와 종목 화면 주문까지 간 비율 (초보의 고위험 상품 유입 감시)

## 5. 해결 방법

| | 홈 | 종목 화면 |
|---|---|---|
| 질문 | "내일 장 시작 가격 오를까요?" / "지금 차이로 얼마 남아요?" | 두 시장이 어디서, 얼마나, 왜 벌어졌나 |
| 화면 | 확률 1개, 예상 시작 가격, 10번 중 8번 범위, 금액별 순차익 | 두 시장 겹친 차트, 호가 3개(perp·KRX·NXT), 주문 |
| 용어 | perp → "해외 24시간 시장" | 원어 그대로 |

**종목 화면 차트**
- 두 시장 캔들/라인 겹침, 시장별 on/off, 시장별 거래량
- 배경색으로 정규장·넥스트레이드·휴장(perp만 거래) 구분
- 괴리율 패널: 장중은 진하게, 휴장 중(직전 종가 대비)은 연하게
- 개장 수렴 표시: 개장 봉 위에 "perp가 말한 갭을 주식이 몇 % 따라갔는지"
- 휴장 중에는 예상 시작 가격선과 80% 구간
- 뉴스 말풍선 (하루 1건, 출처 확인된 것만) → 누르면 요약과 원문 링크
- 이동평균, 그물망, 볼린저, 일목균형, VWAP, RSI, MACD, 펀딩비

**개장 수렴 지표** (표·차트·API 공통)
- `따라간 정도` = 실제 장 시작 가격 갭 ÷ perp가 말한 갭. 100%면 perp대로 열림
- `만난 지점` = 개장 후 1시간 동안 두 가격이 만난 위치. 0이면 perp가 주식 쪽으로, 1이면 주식이 perp 쪽으로 이동

**순차익 계산**

`순차익 = |괴리율| − 주식 수수료·세금 − perp 수수료 − 환전 비용 − 보유 중 펀딩비`

| 항목 | 기본값 | 근거 |
|---|---|---|
| 주식 | 왕복 수수료 0.03% + 매도세 0.20% | 2026년 코스피 증권거래세·농특세 합계로 가정 |
| perp | 왕복 0.018% | HL 기본 0.045% × HIP-3 배수 2 × growth mode 0.1 |
| 환전 | (0.05% + 호가 스프레드 절반) × 2 ÷ 레버리지 | 업비트 원화마켓 수수료, 증거금만 환전 |
| 펀딩 | 시간당 펀딩 × 1시간 | 숏이면 받고 롱이면 냄 |

- 개인은 주식 공매도가 어려워서 **perp가 쌀 때(주식 매도 필요)는 '실행 불가'로 표시**
- 모든 비용은 API 파라미터로 바꿀 수 있음

## 6. 주요 결정과 이유

| 결정 | 이유 |
|---|---|
| **환율은 원/USDC (업비트 실시간)** | perp는 USDC로 정산. 국내 투자자가 실제로 돈을 옮기는 경로가 원 → USDC라서, 은행 원/달러 환율보다 체결 가능한 값에 가까움 |
| **증권사 API는 토스증권 Open API** | 실시간 체결·호가 웹소켓, 1분봉(넥스트레이드 포함 통합 시세), 투자자 동향, 장 운영 캘린더, 주문까지 한 곳에서. 브라우저가 직접 못 붙는 웹소켓(헤더 인증·허용 IP)은 서버가 하나만 열어 나눠줌 |
| **코스피200 perp는 제외** | 토스증권 API가 지수를 코스피·코스닥만 제공. 같은 기초자산끼리만 비교 |
| **국내 실주문은 기본 꺼둠** | 토스증권은 모의투자가 없어서 실제 돈이 나감. 서버 주인이 `TOSS_LIVE_ORDERS=1`로 켰을 때만 |
| **예측 모델은 단순 선형 + 정규분포** | 표본이 119번뿐이라 복잡한 모델은 과적합. 설명할 수 있어야 초보가 믿음(H3). 계수 β는 1(perp 그대로) 쪽으로 당겨서 급락일 몇 번에 휘둘리지 않게 함 |
| **개장까지 남은 시간만큼 범위를 넓힘** | 금요일 밤 예측과 월요일 08:59 예측의 확신이 같으면 안 됨. 휴장 시간대 perp 변동성 × 남은 시간 반영 |
| **홈 → 종목 화면 한 갈래** | 요약/상세 모드를 따로 두면 같은 정보가 두 번 나오고 '뭐가 다르지?' 고민이 생김. 초보 질문 2개("오를까?", "얼마 남아?")는 홈과 종목 화면 맨 위에 답하고, 차트·호가·주문은 그 아래에 |
| **예측시장은 v2로 미룸** | 국내 사행성 규제 소지, 금융당국이 해외 perp 이용에 경고한 상황. 먼저 예측 정확도와 신뢰를 쌓는 게 순서 |
| **주문은 기본 미리보기, perp는 테스트넷 기본** | 프로토타입에서 실수 주문 0건이 우선. 실주문은 서버 토큰 + 명시적 전환 필요 |
| **perp 주문은 에이전트 지갑으로만 서명** | 메인 지갑 키가 앱에 들어오지 않음. 에이전트는 주문만 가능, 출금 불가 |
| **MCP는 조회 + 미리보기만** | 에이전트 오작동이 실제 돈으로 이어지지 않게 |
| **뉴스는 하루 1건, 출처 있는 것만** | 차트가 뉴스로 덮이면 안 됨. 틀린 뉴스 1건이 신뢰를 다 깎음 |
| **차트는 TradingView lightweight-charts** | Skia(CanvasKit)는 wasm만 수 MB라 첫 화면이 느려짐. 캔버스 기반, 약 57KB(gzip), 거래소에서 검증된 라이브러리. 종목 화면에서만 내려받음 |
| **디자인 토큰은 토스증권 PC, 키컬러·CTA만 카카오페이** | 증권 사용자가 이미 익숙한 정보 밀도와 컴포넌트(패널, 칩, 호가, 관심 목록). 브랜드 구분은 노랑(#FFEB00) 하나로 충분. 폰트는 토스 전용 서체 대신 가장 가까운 공개 서체 Pretendard |
| **React 19.3.1 / Vite 8.3.5** | 최신 패치 버전이면서 실사용 2위 버전. 2025~26년 React 보안 이슈는 서버 컴포넌트 한정이라 SPA는 해당 없음. Vite는 10월 보안 패치 포함 버전 |

## GA4 설정

1. Google Analytics → 관리 → 속성 만들기 → 웹 스트림 추가 → 측정 ID(`G-…`) 복사
2. Vercel 환경변수 `VITE_GA_ID`에 넣고 재배포
3. 관리 → 맞춤 정의에 등록
   - 이벤트 범위: `kst_window`, `asset`, `from`, `market`
   - 사용자 범위: `first_source`, `first_content`
4. 탐색 → 코호트 탐색: 코호트 = `first_source`, 재방문 조건 = `page_view` 중 `kst_window = preopen`
5. 커뮤니티 글 링크 예시: `https://<도메인>/?utm_source=naver_jongto&utm_medium=community&utm_campaign=bamsai_test1&utm_content=smsn_thu_A`

## 알려진 한계

- 토스증권 API는 허용 IP에서만 호출 가능. 서버 IP가 고정이어야 함
- 토스증권 토큰은 새로 발급하면 이전 토큰이 바로 무효 → 서버는 한 대(한 프로세스)로 운영
- 토스증권은 동시호가 예상체결가를 주지 않아 개장 직전 예상가는 perp 기준만 표시
- 서버 메모리 캐시라 인스턴스가 바뀌면 백테스트를 다시 계산함 (첫 요청 수 초)
- 투자 권유가 아닌 참고 정보. 해외 perp는 국내 투자자 보호 대상이 아님
