# 밤사이

국내 시장이 닫힌 밤과 주말에도 거래되는 **하이퍼리퀴드 한국 주식 perp** 가격으로
**① 밤사이 해외 가격과, 과거에 국내 시장이 그 방향대로 열린 비율**, **② 두 시장 사이 가격 차이 거래(시세차익) 기회가 있는지** 알려주는 서비스. 장 시작 가격은 사용자가 직접 가늠함

- 웹앱: **https://bamsai.kr**
- API 문서: [bamsai.kr/api/openapi.json](https://bamsai.kr/api/openapi.json) · MCP: `https://bamsai.kr/api/mcp` · 화면 안내: [bamsai.kr/developers](https://bamsai.kr/developers)
- 1\~2장 요약 PRD: [docs/prd-summary.md](docs/prd-summary.md)

> **English** — Bamsai prices Korean blue chips (Samsung Electronics, SK hynix, Hyundai Motor) 24/7 from their Hyperliquid perps (trade.xyz), converted to KRW at the Upbit KRW/USDC rate. While the Korean market is closed it shows the overseas price, how often past Korean opens followed it at the same stage of the US session, and the gap between the two markets net of fees, tax, FX, funding, slippage and order lag.
> MCP endpoint `https://bamsai.kr/api/mcp` (Streamable HTTP, no key) or `npm run mcp:stdio` locally. Tools: `predict_open`, `get_arbitrage`, `get_convergence_history`, `get_news`, `preview_pair_order` (preview only, never sends orders). REST: [OpenAPI](https://bamsai.kr/api/openapi.json), 300 requests/min per IP. MIT licensed. The rest of this README is in Korean.

# PRD

## 개요

국내 시장이 닫혀 있는 65%의 시간(넥스트레이드 포함) 동안에도 삼성전자·SK하이닉스·현대차 가격은 해외 24시간 시장에서 움직임.
이 가격을 원화로 바꿔 보여주고, **과거에 국내 시장이 그 방향대로 열린 비율과 보통 시작하는 범위**를 함께 보여줌. 같은 숫자를 API·MCP로 열어 **LLM으로 자동매매 봇을 운영하는 개인 투자자(초기 타겟)**의 봇이 바로 판단에 쓰게 함. 두 시장에 자금을 둔 사용자에게는 **비용 뺀 가격 차이 거래 기회**를 계산해 주문 화면(출시 예정)까지 연결.

## 2. 타겟 고객

| 구분 | 고객 | 이 고객을 고른 이유 | 주로 쓰는 것 |
|---|---|---|---|
| **초기 타겟** | **LLM으로 국내 주식 자동매매 봇을 운영하는 개인 투자자.** 어떤 LLM·에이전트를 쓰든 API·MCP로 숫자를 받아 봇이 판단. 하이퍼리퀴드에서 한국 주식 perp를 함께 거래하는 사람 포함 | 이미 자동주문·전략·분석 도구를 직접 만들어 쓰고 있어 설명 비용이 낮음. 하이퍼리퀴드 달러 가격, 원/USDC 환율, 국내 시세(정규장·넥스트레이드)를 직접 모아 맞추고 적중률 검증·비용 계산까지 해야 하는 불편이 가장 큼. 쓰는지 안 쓰는지가 호출 수로 바로 보여 검증이 빠름 | API · MCP, 웹 화면(봇이 쓰는 숫자를 눈으로 확인) |
| **확장 타겟** | 삼성전자·SK하이닉스 등 **국내 주식을 거래하는 일반 투자자** | 개인 보유자가 많은 대표 종목이고 perp 거래대금도 가장 큼. 아침 8시 국내 시장이 열리기 전에 판단할 일이 매일 있음. 초기 타겟이 숫자를 꾸준히 쓰면 그 근거로 증권 앱 화면으로 넓힘 | 홈 · 종목 상세 |

**초기 타겟의 결정의 순간 — 봇이 무엇을 보고 언제 움직이나**
- 국내 주식 봇: 미국장이 닫힌 뒤(06\~08시) 개장 전 포지션과 장전 주문 가격을 정할 때 (`predict_open`)
- 두 시장을 함께 거래하는 봇: 가격 차이가 평소보다 벌어졌을 때 (`get_arbitrage`, 비용 뺀 금액)
- 하이퍼리퀴드 perp 봇: 국내 장중에 국내 가격·투자자 동향이 바뀔 때 (원화 환산 가격, 지난 개장 기록)

**확장 타겟의 결정의 순간 — 아침 8시 넥스트레이드가 열릴 때 바로 사고팔지, 기다릴지**
- 보유자는 갭이 생기기 전(밤)에 팔 수 없음. 할 수 있는 결정은 '08시에 바로 거래할지, 가격이 자리 잡을 때까지 기다릴지'와 '장전 주문을 얼마에 걸지'
- 하이퍼리퀴드가 밤새 1% 넘게 움직인 날, 08\~09시에 국내 가격이 하이퍼리퀴드 가격 쪽으로 가서 만난 경우가 삼성전자 72%·SK하이닉스 75%, 반대(하이퍼리퀴드가 국내 쪽으로)는 11%·10% (2026-04\~11, 105·108번). 개장 직후 국내 가격이 하이퍼리퀴드 원화 가격과 크게 벌어져 있으면 그쪽으로 좁혀질 가능성이 큼
- 예: 11/6 삼성전자는 하이퍼리퀴드 07시 −9.5%, 08:00\~08:10 평균 −11.9%로 과하게 시작한 뒤 10:28 −7.4%로 되돌아옴

**일반 투자자 화면과 perp의 경계**: 홈 카드·지난 개장 기록·소개는 국내 주식 판단까지만. 해외 perp는 국내 투자자 보호 대상이 아니라서(금융위·금감원 2026-10-16 유의사항 발표) perp 계좌가 없는 사람에게 권하지 않음. 가격 차이 거래와 perp 주문은 이미 하이퍼리퀴드를 쓰는 사용자용 별도 트랙이고, 증권 앱 버전에서는 국내 주문만 연결

**주문 화면과 출시 알림 신청**: 해외 가격과의 차이를 보다가 그 자리에서 주문까지 하고 싶은 사용자가 있는지 확인하려고, 종목 상세에 주문 화면(차트 \| 호가 \| 주문)과 출시 알림 신청(이메일)까지 만듦. 대상이 넓어지는 방향이라 핵심 범위와 나눈 별도 트랙으로 두고, 실제 주문은 보내지 않음. 주문 버튼 클릭과 알림 신청 수로 수요를 잼(H4)

|---|---|---|---|
| **H1 신호** | 국내 시장이 모두 닫힌 동안(20:00\~08:00) 하이퍼리퀴드에서 충분히 거래됐다면, 그 가격이 움직인 방향대로 **다음 날 08:00 국내 시장도 80% 이상 같은 방향으로 시작**한다 | 가장 높음 | 서비스 존재 이유가 없음 |
| **H5 에이전트** (초기 타겟) | LLM 자동매매 봇 운영자에게 밤사이 숫자를 API·MCP로 열면 **봇이 매주 반복해서 호출**한다 | 높음 | 초기 타겟 가정이 틀림. 웹 화면 중심(확장 타겟)으로 순서를 바꿈 |
| **H2 가치** (확장 타겟) | 보유 종목의 밤사이 해외 가격과 "그 방향대로 열린 비율"을 보여주면 **장 시작 전에 다시 찾아온다** | 높음 | 신기한 숫자로 끝나고 습관이 안 됨 |
| **H3 신뢰** | 지난 개장 기록을 같이 보여줘야 **숫자를 믿고 행동한다** | 중간 | 숫자만 보고 떠나거나, 반대로 맹신 |
| **H4 전환** (확장 트랙) | 수수료·세금까지 뺀 **가격 차이 거래(시세차익) 기회**를 보여주면 조회가 **주문 버튼 클릭**으로 이어진다 (주문은 출시 전이라 클릭 시 출시 알림 신청) | 중간 | 종목 상세가 구경용에 그침 |

**H1은 출시 전 과거 데이터로 먼저 검증**

**왜 이 기준인가**
- 개인 투자자는 정규장(09:00–15:30)뿐 아니라 넥스트레이드(08:00–08:50, 15:30–20:00)에서도 거래함 → '국내 시장'은 둘을 합친 08:00–20:00
- 국내가 정말 닫힌 시간은 **20:00 → 다음 거래일 08:00**(평일 12시간, 주말·연휴는 더 김). 이때 움직이는 건 하이퍼리퀴드뿐
- 그래서 **기준 = 20:00 국내 마지막 가격**, **맞힐 대상 = 08:00 국내 시장이 다시 열렸을 때 개인이 거래할 수 있는 가격**
- 08:00 첫 체결 한 건은 거래가 적어 들쭉날쭉함 → **08:00\~08:10 거래량 가중 평균**을 씀 (아래 비교표에서 5분·10분 평균이 가장 안정적)

**채점 방법**
- 하이퍼리퀴드 움직임 = 08:00 직전(07:00\~07:59 1시간 봉 종가, 그 시각 환율로 원화 환산) 하이퍼리퀴드 가격 ÷ 전날 20:00 국내 가격 − 1. 08:00 넥스트레이드 첫 체결이 오라클로 들어가 perp가 튀는 경우(2026-07-28)를 피하려고 08:00 직전 가격을 씀
- 국내 움직임 = 08:00\~08:10 평균 가격 ÷ 전날 20:00 국내 가격 − 1
- 둘의 방향(+/−)이 같으면 '따라감'. 둘 중 하나라도 ±0.05% 안쪽이면 '거의 그대로'로 따로 표시하고 비율에서 뺌
- **조건: 그날 밤(20:00\~08:00) 하이퍼리퀴드 거래대금 100만 달러 이상.** 거래가 적으면 몇 건의 주문으로도 가격이 흔들려 '시장의 판단'으로 보기 어려움 (아래 근거)

### 보통 시작 범위 계산법

화면의 '보통 이 안에서 시작(80% 구간)'과 지난 개장 기록 채점은 아래 순서로 계산함. API에는 예상 가격·`probUp`도 남아 있지만 화면에서는 쓰지 않음 (확률이 약속처럼 읽혀서). 사용자용 설명은 소개 페이지('밤사이는 이렇게 계산해요')에 있음. 모델은 일부러 단순하게 둠 (표본이 종목별 140번 남짓이라 복잡하면 과적합되고, 초보도 이해할 수 있어야 해서)

1. **밤사이 차이** `g` = 지금 하이퍼리퀴드 가격(원화) ÷ 어제 20:00 국내 가격 − 1
2. **예상 움직임** `μ` = α + β × g
   - β = 과거 개장에서 국내가 하이퍼리퀴드 움직임을 평균 몇 배 따라갔는지. 1(그대로 따라감) 쪽으로 당겨서 급락일 몇 번에 흔들리지 않게 함
   - α = 하이퍼리퀴드와 상관없이 생기는 평균 차이 (거의 0)
3. **불확실성** `σ` = √(과거 예측이 빗나간 폭² + β² × 하이퍼리퀴드 시간당 변동성² × 장 열리기까지 남은 시간)
   - 빗나간 폭은 평일 밤 / 주말·연휴를 따로 계산 (주말이 더 큼)
   - 남은 시간이 길수록 하이퍼리퀴드가 더 움직일 수 있으니 범위를 넓힘
4. **결과**
   - 예상 가격 = 어제 20:00 가격 × (1 + μ)
   - `probUp`(API 전용, 화면에는 안 씀) = 정규분포에서 0보다 클 확률 Φ(μ / σ)
   - 예상 범위(80% 구간) = μ ± 1.28σ. 10번 중 8번은 이 안에서 시작하도록 잡은 범위
5. **검증**: 그날 이전 데이터로만 2\~4를 계산해 그날 결과와 비교 (walk-forward). 미래 정보가 섞이지 않음

**예시: SK하이닉스, 2026-11-04 아침** (실제 채점과 같은 방식: 11월 3일까지 137번 개장으로 맞춘 계수 α −0.22%, β 0.875, 평일 밤 σ 1.36%)

| 단계 | 값 |
|---|---|
| 어제(11/3) 20:00 국내 가격 | 1,414,000원 |
| 11/4 08:00 직전(07:59) 하이퍼리퀴드 가격 (원화) | 1,461,621원 → `g` = **+3.37%** |
| 예상 움직임 `μ` = −0.22% + 0.875 × 3.37% | **+2.73%** → 예상 가격 약 **1,452,600원** |
| 불확실성 `σ` (08:00이라 남은 시간 0) | 1.36% |
| `probUp` Φ(2.73 / 1.36) (API 전용) | 약 98% (97.8%) |
| 예상 범위 2.73% ± 1.74% | +0.99% \~ +4.47% → 약 1,428,000원 \~ 1,477,200원 |
| **실제** 08:00\~08:10 평균 | **1,451,776원 (+2.67%)** → 방향 맞음, 예상 범위 안 |

- 지금(11/5) 기준 계수는 α −0.24%, β 0.88, σ 1.37%로 매일 조금씩 바뀜. 예시는 그날 아침 실제로 썼을 계수로 계산함 (서버 채점 값 +2.7289%와 일치)

**North Star: 밤사이 API·MCP를 호출한 주간 외부 호출자 수 (초기 타겟)**
→ 선정 이유: 초기 타겟의 봇이 밤사이 숫자를 실제 판단에 쓰고 있다는 가장 직접적인 신호. 한 번 붙여 보고 마는지, 매주 다시 부르는지가 핵심
- 정의: 실제로 데이터를 가져간 호출(REST `/v1` 조회, MCP 도구 호출)만 남기는 GA 이벤트 `api_data_call`의 주간 고유 호출자. 연결 확인(`initialize`·`tools/list`), 목록 사이트 점검, 오류 응답, 우리 쪽 확인 호출은 제외
- 호출자 구분: IP와 User-Agent를 비밀 값과 섞은 해시(`caller_id`, 2026-11-07부터). IP 원문은 GA로도 로그로도 남기지 않음. 같은 망에서 같은 도구를 쓰면 한 명, IP가 바뀌면 두 명으로 셀 수 있는 근사값. 그 전 기록은 User-Agent로만 구분돼 사람 수를 알 수 없음
- 신규·재사용자: 그날 처음 본 `caller_id`면 신규, 이전 날에 본 적 있으면 재사용자
- 보조: 개장 전(06\~08시) `predict_open` 호출 수, 2주 연속 호출한 호출자 비율
- 유입: 2026-11-06 공식 MCP Registry(`io.github.eddyParkGG/bamsai`)와 Glama에 등록(원격 연결 `kr.bamsai/bamsai` A등급, 소스 빌드 검사 통과한 서버 `eddyParkGG/bamsaikr` B등급), awesome-mcp-servers·awesome-remote-mcp-servers 목록에 추가 PR 제출(자동 검사 통과, 관리자 머지 대기). 로컬 프로세스로 붙이는 클라이언트용 stdio 실행(`npm run mcp:stdio`) 지원

**확장 타겟 지표: 미국장이 닫힌 뒤 국내 시장 시작 전(06:00\~08:00)에 밤사이 가격을 실제로 본 주간 사용자 수**
→ 선정 이유: H2(습관)와 H1(하이퍼리퀴드 신호)이 둘 다 맞아야 오르는 숫자. 06시 이후가 하이퍼리퀴드 가격이 가장 정확한 시간대(위 표)이고, 08시에 넥스트레이드가 열리기 전 판단하는 순간이라 이 시간대만 셈
- 정의: GA `prediction_view` 이벤트 중 `kst_window = preopen`(06:00\~08:00 KST)인 고유 사용자. 홈·종목 페이지에 들어왔을 뿐인 `page_view`는 세지 않음
- 측정 상태: 2026-11-06에 GA 맞춤 측정기준(`kst_window` 등)을 등록해 그날부터 측정 가능. 그 전 데이터로는 계산할 수 없음
- 다음 단계에서 이어 볼 것: 같은 사용자의 주간 재방문률, (주문 출시 후) 개장 직후 주문 전환

**판단 규칙**

- 개장 전 재방문 **15% 이상** → 개장 전 알림(웹 푸시) 바로 개발. 알림이 리텐션을 더 올릴 여지가 큼
- **5\~15%** → 메시지(A/B 중 나은 쪽)와 게시 시각을 바꿔 1회 재실험
- **5% 미만** → '매일 보는 습관' 가설 기각. 주말·연휴 갭 리포트처럼 이벤트성 콘텐츠로 방향 전환
- A/B는 채널 간 차이보다 메시지 차이를 먼저 봄 (채널은 2개뿐이라 비교 의미가 약함)

**주의할 점**

- 커뮤니티 홍보 금지 규정: 정보 공유 형식(주말 갭 수치 + 그래프 캡처)으로 쓰고 링크는 1개만
- 특정 종목 매수·매도 권유 문구 금지 (유사투자자문 오해 방지)

## 5. 해결 방법

| | 홈 | 종목 상세 |
|---|---|---|
| 질문 | "밤사이 해외에선 얼마나 움직였어요? 믿을 만해요?" / "지금 시세차익 기회 있어요?" | 두 시장이 어디서, 얼마나, 왜 벌어졌나 |
| 화면 | 종목 카드 3개 (누르면 종목 상세). 장중: 위 '국내 지금' / 아래 '미국장 닫힌 뒤 · 국내 개장 직전 글로벌 가격'. 장 마감 후: 위 '국내 종가' / 아래 '지금 글로벌 가격'(실시간) + 미국장 단계 + '과거 이 시간대 n%가 이 방향대로 열렸어요'. 아래에 해외 가격과 시세차익 기회(1천만원 기준) | 차트 \| 호가 \| 주문 3단(경계를 끌어 너비 조절, 기본 340px, 페이지 스크롤 없음), 차트 위 '하이퍼리퀴드 지금 · [자세히]'와 그 아래 미국장 단계·과거 적중률 한 줄·'시세차익 · 1천만원이면 약 N원 [시세차익 내기]', 차트 전체화면, 탭 줄 끝 오늘의 이슈, 개장 전 가격·지난 개장 기록·투자자 동향 탭 |
| 용어 | perp → "하이퍼리퀴드", KRX·넥스트레이드 → "국내 시장", 시가 → "장 시작 가격" | 같음 (원화 환산 기준) |

**종목 상세 차트**
- 두 시장 캔들/라인 겹침, 시장별 on/off, 시장별 거래량
- 배경색으로 국장 개장(정규장·넥스트레이드)·휴장(하이퍼리퀴드만 거래) 구분, 일봉 포함
- 하이퍼리퀴드 일봉은 국내 거래일과 같은 저녁 8시\~저녁 8시 기준으로 다시 묶음 (거래소 일봉은 UTC 하루라 13시간 어긋남)
- 가격 차이 패널: 장중은 진하게, 휴장 중(직전 종가 대비)은 연하게. 하이퍼리퀴드 상장일 세로선
- 따라간 정도 패널: 하이퍼리퀴드가 1% 이상 움직인 날, 그 움직임을 국내 시장이 몇 % 따라 시작했는지 막대로 (100 점선 = 같은 만큼)
- 보조 패널(거래량·가격 차이·따라간 정도·펀딩비·RSI·MACD)마다 제목과 물음표 설명, 지표를 켜면 자동으로 붙음
- 휴장 중에는 보통 시작 범위(점선 2개), 시세차익이 생기면 그 가격에 '시세차익 내기' 버튼
- 뉴스 말풍선 (하루 1건, 출처 확인된 것만) → 누르면 요약과 원문 링크
- 이동평균, 그물망, 볼린저, 일목균형, VWAP, RSI, MACD, 펀딩비

**따라간 정도 지표** ('지난 개장 기록' 표·차트·API 공통)
- `따라간 정도` = 08:00\~08:10 국내 움직임 ÷ 밤사이 하이퍼리퀴드 움직임. 100%면 그대로 따라 시작. 차트에는 하이퍼리퀴드가 1% 이상 움직인 날만 표시 (작은 움직임은 비율이 의미 없음)
- `만난 지점` = 08:00\~09:00 동안 두 가격이 만난 위치. 0이면 하이퍼리퀴드가 국내 쪽으로, 1이면 국내가 하이퍼리퀴드 쪽으로 이동

**가격 차이 거래 (화면 이름 '시세차익')**

- 전제: 하이퍼리퀴드 지갑(USDC)과 국내 증권 계좌에 **미리 자금을 둔 상태**. 원화를 USDC로 바꿔 옮기는 시간은 거래 순간에 들지 않음
- 방법: 두 가격 차이가 평소보다 벌어졌을 때 비싼 쪽을 팔고 싼 쪽을 산 뒤, 차이가 평소 수준으로 돌아오면 둘 다 정리
- 성격: **무위험 차익이 아니라 평소 차이로 돌아온다는 데 거는 거래**(통계적 차익). 같은 순간에 사고팔아 확정되는 이익이 아님
- 아직 반영 못 한 위험: 차이가 언제 좁혀질지 모름(펀딩비는 1시간 보유로 가정), 양쪽에 자금을 묶어 두는 부담

`순차익 = |가격 차이 − 평소 차이| − 슬리피지 − 주문 간 시차 비용 − 주식 수수료·세금 − perp 수수료 − 환전 비용 − 보유 중 펀딩비`

- 두 시장 가격 차이는 0으로 돌아가지 않고 '평소 수준'에서 움직임. 정규장 시간 월별 중간값이 2026년 9월 약 −0.7\~+0.1%, 10월 +0.9\~1.0%, 11월 +0.5% (세 종목 비슷)
- 그래서 **평소 차이 = 최근 5거래일 정규장 1시간 가격 차이의 중간값**으로 두고, 지금 차이가 평소보다 더 벌어진 만큼만 기회로 봄. 처음에는 0을 기준으로 계산해서, 평소 수준인 날에도 '1천만원 기준 약 17,000원 남아요'로 보였던 문제를 고침
- 화면 목록은 두 경우만: 비용을 빼고 남으면 '+N원', 아니면 '아직 시세차익 기회가 없어요'. 이유(평소 수준·비용이 더 큼·주식 매도 필요)는 차트 위 설명에서 봄
- **호가 기준 체결가**: 1천만원(`notionalKrw`)만큼 하이퍼리퀴드는 매수 호가를, 국내는 매도 호가를 쌓아 평균 체결가를 계산. 중간 가격과의 차이가 슬리피지. 보이는 호가로 다 못 채우면 '호가 잔량이 부족해 최대 N만원까지'로 표시하고 채울 수 있는 금액으로 계산
- **주문 간 시차**: 두 주문은 동시에 체결되지 않음. 최근 60분 1분 변동성 × √(시차/60초), 시차 기본 3초(`lagSec`)
- 오라클이 튀는 순간에도 숨기지 않고 실제 호가 그대로 계산 (그 가격에 실제로 체결되므로). 대신 추가 급변 시 청산 위험이 큼

| 항목 | 기본값 | 근거 |
|---|---|---|
| 주식 | 왕복 수수료 0.03% + 매도세 0.20% | 2026년 코스피 증권거래세·농특세 합계로 가정 |
| perp | 왕복 0.018% | HL 기본 0.045% × HIP-3 배수 2 × growth mode 0.1 |
| 환전 | (0.05% + 호가 스프레드 절반) × 2 ÷ 레버리지 | 업비트 원화마켓 수수료, 증거금만 환전 |
| 펀딩 | 시간당 펀딩 × 1시간 | 숏이면 받고 롱이면 냄 |
| 슬리피지 | 1천만원어치 호가를 쌓은 평균 체결가 − 중간 가격 | 두 시장에서 받아 오는 호가 단계까지 |
| 주문 간 시차 | 1분 변동성 × √(3초/60초) | 최근 60분 원화 환산 1분봉 |

- 개인은 주식 공매도가 어려워서 **perp가 쌀 때(주식 매도 필요)는 기회로 세지 않음**
- 모든 비용은 API 파라미터로 바꿀 수 있음

## 6. 주요 결정과 이유

| 결정 | 이유 |
|---|---|
| **환율은 원/USDC (업비트 실시간)** | perp는 USDC로 정산. 국내 투자자가 실제로 돈을 옮기는 경로가 원 → USDC라서, 은행 원/달러 환율보다 체결 가능한 값에 가까움 |
| **증권사 API는 토스증권 Open API** | 카카오페이증권은 오픈 API가 없어서, 발급이 쉬운 토스증권 Open API를 사용. 실시간 체결·호가 웹소켓, 1분봉(넥스트레이드 포함 통합 시세), 투자자 동향, 장 운영 캘린더, 주문까지 한 곳에서. 브라우저가 직접 못 붙는 웹소켓(헤더 인증·허용 IP)은 서버가 하나만 열어 나눠줌 |
| **예측·시세차익은 국내 주식 3종만, 나머지는 하이퍼리퀴드 가격만** | 하이퍼리퀴드의 한국 상품 7개(삼성전자·SK하이닉스·현대차·SK하이닉스 ADR·코스피200·EWY·KORU)를 다 보여주되, 같은 기초자산의 국내 가격이 있는 국내 주식 3종만 예측·시세차익을 계산. ADR은 보통주로 바꿀 수 없고, 코스피200은 증권사 API에 실시간 지수가 없고, EWY·KORU는 미국 ETF라 비교 대상이 없음 |
| **화면은 Vercel, API 서버는 Fly.io (고정 IP 서버 1대)** | 토스증권 Open API는 허용 IP에서만 호출되고, 토큰을 새로 받으면 이전 토큰이 바로 무효가 됨. 그래서 고정 출구 IP를 가진 서버가 항상 1대만 떠 있어야 함. Vercel·Firebase 같은 서버리스 함수는 요청마다 인스턴스가 여러 개 뜰 수 있어 토큰이 서로를 끊고, 고정 IP는 유료 옵션. Fly는 머신 1대 + 고정 출구 IP(월 $3.6)로 월 $8 안팎. 화면(정적 파일)은 Vercel이 내보내고 `/api`만 Fly로 넘김 |
| **국내 실주문은 기본 꺼둠** | 토스증권은 모의투자가 없어서 실제 돈이 나감. 공개 서버(bamsai.kr)는 꺼두고 미리보기만 함. 남의 계좌로 대신 주문하지 않음. 실주문은 각자 이 저장소를 직접 띄우고 본인 토스증권 키·허용 IP·`TOSS_LIVE_ORDERS=1`·`API_TOKEN`을 넣었을 때만, 그 본인 계좌로 |
| **'국내 시장' = 정규장 + 넥스트레이드 (08:00–20:00)** | 개인이 실제로 거래할 수 있는 시간 전체. 15:30\~20:00 넥스트레이드 움직임은 이미 국내에서 보이는 정보라, 이걸 예측으로 치면 실력이 부풀려짐. 그래서 기준은 20:00 마지막 가격, 대상은 08:00 재개장 가격 |
| **08:00\~08:10 평균 가격으로 채점** | 첫 체결 한 건은 거래가 적어 튐. 5·10·30분 평균과 정규장 09:00을 비교해 가장 안정적인 10분 평균 선택 |
| **보통 시작 범위 모델은 단순 선형 + 정규분포** | 표본이 종목별 140번 남짓이라 복잡한 모델은 과적합. 설명할 수 있어야 초보가 믿음(H3). 계수 β는 1(하이퍼리퀴드 그대로) 쪽으로 당겨서 급락일 몇 번에 휘둘리지 않게 함. 계산법은 3장 '보통 시작 범위 계산법' |
| **장 열리기까지 남은 시간만큼 범위를 넓힘** | 금요일 밤 예측과 월요일 07:59 예측의 확신이 같으면 안 됨. 닫힌 시간대 하이퍼리퀴드 변동성 × 남은 시간 반영 |
| **홈 → 종목 상세 한 갈래** | 요약/상세 모드를 따로 두면 같은 정보가 두 번 나오고 '뭐가 다르지?' 고민이 생김. 초보 질문 2개("밤사이 해외에선 얼마나 움직였어?", "지금 남는 돈 있어?")는 홈 카드에서 답하고, 종목 상세에서는 같은 답을 차트 위 해당 가격에 붙여 보여줌 |
| **예측시장은 v2로 미룸** | 국내 사행성 규제 소지, 금융당국이 해외 perp 이용에 경고한 상황. 먼저 예측 정확도와 신뢰를 쌓는 게 순서 |
| **화면 주문은 '출시 예정' + 알림 신청, API는 기본 미리보기(dryRun)** | 프로토타입에서 실수 주문 0건이 우선. 대신 주문 버튼 클릭과 알림 신청으로 실제 수요(H4)를 잼. API 실주문은 서버 토큰 + 명시적 전환 필요, perp는 테스트넷 기본 |
| **API의 perp 주문은 에이전트 키로만 서명** | 메인 지갑 키가 서버에 들어오지 않음. 에이전트는 주문만 가능, 출금 불가 |
| **MCP는 조회 + 미리보기만** | 에이전트 오작동이 실제 돈으로 이어지지 않게 |
| **뉴스는 하루 1건, 출처 있는 것만** | 차트가 뉴스로 덮이면 안 됨. 틀린 뉴스 1건이 신뢰를 다 깎음 |
| **차트는 TradingView lightweight-charts** | Skia(CanvasKit)는 wasm만 수 MB라 첫 화면이 느려짐. 캔버스 기반, 약 57KB(gzip), 거래소에서 검증된 라이브러리. 종목 상세에서만 내려받음 |
| **디자인 토큰은 토스증권 PC, 키컬러·CTA만 카카오페이** | 카카오페이증권은 PC 버전이 없어서, 간편한 UX로 잘 알려진 토스증권 PC를 참고. 증권 사용자가 이미 익숙한 정보 밀도와 컴포넌트(패널, 칩, 호가, 검색, 필터). 하이퍼리퀴드는 그쪽 키컬러에 가까운 민트로 구분. 브랜드 구분은 노랑(#FFEB00) 하나로 충분. 폰트는 토스 전용 서체 대신 가장 가까운 공개 서체 Pretendard |
| **React 19.3.1 / Vite 8.3.5** | 최신 패치 버전이면서 실사용 2위 버전. 2025\~26년 React 보안 이슈는 서버 컴포넌트 한정이라 SPA는 해당 없음. Vite는 10월 보안 패치 포함 버전 |

# AI 활용 과정

Claude Code(Opus 5.5)와 대화하며 기획부터 배포까지 진행

**AI로 만든 것과 제품 안의 계산은 다름**
- AI는 개발 도구로만 씀: 리서치, 데이터 검증, 백테스트 코드 작성·분석, 구현, QA
- 화면과 API의 숫자는 전부 실제 시세 데이터로 통계 계산이 만듦. 서비스 실행 중에 LLM API를 부르지 않고, LLM이 금융 수치를 만들거나 바꾸지 않음

# 실행 방법

```bash
npm install
cp .env.example .env.local   # TOSS_CLIENT_ID / TOSS_CLIENT_SECRET 입력 (토스증권 WTS > 설정 > Open API)
npm run dev                  # 웹 http://localhost:5173 (API는 배포 서버 bamsai-api.fly.dev 사용)
npm run dev:local            # 서버 코드 수정 시: 로컬 API http://localhost:8787/api 도 실행. 켜는 동안 배포 서버의 토스 토큰이 끊김 (토스 키는 하나뿐이고 새 토큰이 이전 토큰을 무효화)
npm run mcp:stdio            # MCP를 표준 입출력으로 실행 (Claude Desktop 등 로컬 프로세스로 붙이는 클라이언트용). 조회 도구는 키 없이 동작
npx tsx --env-file=.env.local server/scripts/backtest.ts        # 백테스트 결과 출력 (서버를 끄고 실행: 토스 토큰이 서로를 무효화함. 서버가 켜져 있으면 /api/v1/convergence로 확인)
npx tsx --env-file=.env.local server/scripts/build-sessions.ts  # 지난 국내 시장 하루 가격(20:00 마지막 가격·08:00~08:10 평균·정규장 시작·종가) 저장 (배포 전, 서버를 끄고 실행)
```

| 환경변수 | 용도 | 없으면 |
|---|---|---|

| `TOSS_LIVE_ORDERS` | `1`이면 API 국내 실주문 허용 (실제 돈). 화면은 항상 '출시 예정' | API는 미리보기만 |

| `HL_ALLOW_MAINNET` | `1`이면 메인넷 주문 허용 | 테스트넷만 |

## GA4 설정

> 가설별 실험 계획·결과 기록과 GA 이벤트·파라미터 전체 목록(어느 화면에서 언제 보내는지)은 [`docs/experiments/`](docs/experiments/README.md)에 정리함

1. Google Analytics → 관리 → 속성 만들기 → 웹 스트림 추가 → 측정 ID(`G-…`) 복사
2. Vercel 환경변수 `VITE_GA_ID`에 넣고 재배포
3. 관리 → 맞춤 정의에 등록
   - 이벤트 범위: `kst_window`, `asset`, `from`, `market`, `tab`, `mode`, `side`, `api_path`, `caller`, `mcp_call`
   - 사용자 범위: `first_source`, `first_content`
   - 주요 이벤트(전환): `launch_notify_signup`, `order_submit`, `model_explain_open`
4. 탐색 → 코호트 탐색: 코호트 = `first_source`, 재방문 조건 = `page_view` 중 `kst_window = preopen`
5. 커뮤니티 글 링크 예시: `https://bamsai.kr/?utm_source=dc_stock&utm_medium=community&utm_campaign=bamsai_test1&utm_content=smsn_thu_A`

## 운영하며 고친 것 (시스템)

배포 후 실제로 돌려 보며 찾은 문제와 고친 방법. 숫자는 Fly 서버 로그와 직접 측정 기준.

| 날짜 | 문제 | 원인 | 고친 방법 | 결과 |
|---|---|---|---|---|
| 11/6 | iPhone 등 일부 브라우저에서 화면이 계속 로딩 | Vercel CDN이 zstd로 압축된 API 응답을 캐시해서, zstd를 못 읽는 브라우저에도 그대로 줌 | API 서버가 직접 gzip으로 압축 | iPhone Safari 프로필 15회 요청 모두 정상 |
| 11/6 | 봇·과도한 호출에 비용 위험 | 호출 제한 없음 | IP당 1분 300회(REST·MCP 합산), 넘으면 429 | 화면 하나가 1분 약 55회라 여러 탭도 여유 |
| 11/6 | 국내 시세가 가끔 비거나 502 | 토스 API는 그룹별 초당 한도(캔들 20, 지수 캔들 5 등)가 있는데, 화면 하나가 여러 API를 동시에 부르고 접속자가 겹치면 넘침 | 토스 호출을 API 그룹별 대기열로 공개 한도보다 낮게 보냄(지수 캔들 4/초, 캔들 15/초 …). 한도 초과 시 1·2·3초 간격 재시도. 1분마다 그룹별 호출·초과 수를 로그로 남김 | 1\~2초마다 나던 한도 초과 → 분당 0\~2회. 재시작 직후 1분에 캔들 423회도 초과 0 |

## 한계 메모

- **국내 시세 이용 조건**: 토스증권 오픈 API 약관(제3조 ③)은 시세를 "개인투자자 본인의 매매 목적에 한하여" 쓰고 제3자 제공·배포·상업적 활용을 하지 않도록 정함. 공개 사이트로 국내 시세를 보여주는 이 프로토타입은 이 조건을 넘을 수 있음. 실제로 출시한다면 증권사가 이미 계약한 정식 시세(코스콤 등 시세 제공업체)를 써야 함. 무료 공공 출처(KRX Open API, 공공데이터포털 금융위 주식시세)는 일별·T+1 데이터라 저녁 8시 넥스트레이드 종가와 아침 8:00\~8:10 분봉을 대신할 수 없음
- **하이퍼리퀴드 한국 주식 perp와 오라클**: 2026년 2월 상장 후 거래가 성장세(SK하이닉스 perp 월 거래대금 3월 1.2억 달러 → 10월 70억 달러, 시장 상황에 따라 월별 변동. 11/6 기준 trade.xyz 주식 perp 전체 24시간 거래대금 약 96억 달러). 다만 perp 가격은 오라클(기초 시장이 열려 있을 땐 외부 체결가, 닫혀 있을 땐 자체 계산 가격)에 묶여 있음. 2026-07-28 08:00 넥스트레이드 프리마켓에서 SK하이닉스 1주가 하한가(127만 2천 원, −29.99%)에 체결되자 이 가격이 오라클에 들어가 perp가 17.9% 급락했고, 약 5,700만 달러의 롱이 청산됨(보도 기준). 거래가 얇은 시점의 체결 하나로 청산을 일으키고 반대편에서 이익을 내는 것이 구조적으로 가능하다는 뜻(국내에서는 시세조종에 해당할 수 있음). 밤사이의 비교 시점(08:00)과 같은 시각이라, 비교 가격은 08:00 직전(07:59) 가격을 씀. 다음 단계로 급변 구간 표시와 거래량 가중 평균 가격으로 보정(8. 다음 액션)
- 토스증권 API는 그룹별 초당 한도(캔들 20, 현재가 15, 지수 캔들 5 등)가 있어 서버가 그룹마다 한도 아래로 줄 세움. 몰리면 국내 시세 갱신이 잠깐 늦어질 수 있음
- 시세차익의 호가 잔량은 받아 오는 호가 단계까지만 반영(보이지 않는 잔량은 모름). 주문 간 시차 비용은 변동성 기반 근사값
- 토스증권 API는 허용 IP에서만 호출 가능. 서버 IP가 고정이어야 함
- 토스증권 토큰은 새로 발급하면 이전 토큰이 바로 무효 → 서버는 한 대(한 프로세스)로 운영
- 토스증권은 동시호가 예상체결가를 주지 않아 개장 직전 예상가는 perp 기준만 표시
- 서버 메모리 캐시라 인스턴스가 바뀌면 백테스트를 다시 계산함 (첫 요청 수 초)
- 하이퍼리퀴드 API는 간격별로 최근 캔들 5,000개만 보관 → 08:00 가격이 필요한 1시간봉은 약 7개월치. 그래서 채점 기간이 2026-04-13부터이고, 서버가 매일 쌓으면 길어짐
- 넥스트레이드 08:00 직후는 거래가 적어 10분 평균도 가끔 튈 수 있음. 현대차처럼 거래가 적은 종목은 영향이 더 큼
- 투자 권유가 아닌 참고 정보. 해외 perp는 국내 투자자 보호 대상이 아님
